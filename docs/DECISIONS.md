# 看盘任务与共享K线

「暂停自主操作」按钮已移除。定时任务通过实例设置中的「开启定时自主看盘」管理；历史paused实例升级后恢复running，但定时auto设为false，避免未经确认恢复自动任务。

## 手动、定时与风险事件

「让她看一次盘」提交到持久队列，接口立即返回；面板显示排队、执行、冷却、失败与最近摘要，不再等模型调用结束才返回HTTP。重复点击不会创建多个相同任务。所有实例的看盘任务串行执行。

在设置的API页配置每实例的任务上限：默认最短间隔10分钟、滚动一小时最多6次，可调低触发频率（间隔10分钟～24小时，上限1～6次/小时）。手动、定时与风险任务共用额度，失败尝试也计数；额度按完整看盘任务计算，工具循环里的多次模型请求不是多个看盘任务。普通聊天和每日日记不计入此看盘额度。频率额度持久保存，重启不会重置。

止损、止盈、模拟强平、保证金不足、本局结束会由已入账日志触发LLM任务，各有独立开关，默认开启。不依赖定时auto开关。连续事件合并；模型运行中发生的新事件排到下一次任务，不会被当前任务完成覆盖。默认每批最多带最近50个事件，更早细节仍可通过交易日志工具读取。

风险通知LLM与向用户发消息是两条流程。夜间仍可让LLM分析；发给用户的风险提醒和摘要仍受主动通知开关和免打扰黑名单控制。普通看盘摘要默认不主动汇报。

LLM使用原有模型路由、人格、已授权聊天、账户、计划、日记和交易日志。运行中的有效行情账户允许正常决策；结束/旧暂停账户只允许查询与复盘，不提供交易、计划修改或通知修改工具。风险事件排队后行情已失效时也降为只读，不编造成交。

失败显示错误并记录任务状态，后续手动重试同样受限频；不会无限自动重试同一个失败模型任务。重启会恢复未完成任务，若有更新事件会合并。首次升级不回放所有历史风险。删除实例或用户会清理关联任务与额度记录。

## K线共享缓存

K线不按交易实例存储：同一行情身份、货币对、周期共用SQLite candles，页面也只有一个共享图表及按来源/货币对/周期划分的内存缓存。切换实例不清空它，切换来源保留其他来源的独立缓存但不混用。

读取先查本地；已覆盖的历史页不重新下载。不同条数的请求、并发请求共用同一品种周期锁。同步检查时间持久化，同一周期内重启或重开页面不重复请求已覆盖数据。扩大显示范围只向缓存最早时间之前补足缺失部分；更新最新行情使用已有增量游标。空历史页也记录覆盖，防止反复请求同一空区间。六品种实时采样仍不断保存。

闭合历史复用本地；新周期需要补最新数据。biquote/OANDA支持时间游标时按游标补量，新浪部分接口只能返回上游限定窗口，插件会复用并去重存储这些结果。Frankfurter继续共享每天参考汇率缓存，不当作实时成交报价或分钟OHLC。

## 验证

离线测试覆盖滚动限频、跨实例额度、事件合并、运行中新事件、恢复、失败反馈、开关和缓存跨实例/重启/分页复用；真实AstrBot离线工具循环验证结束账户只读复盘。没有调用真实云端模型或发送真实用户测试消息。
