# 久留美模拟器

让 AI 带着自己的性格，在真实外汇行情里玩虚拟交易。资金都是虚拟的，交易不发送给券商。

## 当前状态：首个开发里程碑

已实现账户账本、做多做空、市价开平仓、止盈止损、模拟强平、按成交额双边手续费、追加本金、组合结束条件、统一操作日志、交易计划与经验笔记。

随插件提供 `views/dashboard` 面板，包含交易工作台、日志、记忆、游戏和连接设置。支持选择 AstrBot 模型及人格、手动或定时看盘，并为绑定的聊天会话提供独立 AI 工具，保留通用控制台兼容入口。

这是开发预览，不是已完成全部计划的正式版本。尚未在用户服务器加载联调，不会自动安装或修改现有机器人。

## 运行

1. 安装到 AstrBot `data/plugins/astrbot_plugin_kurumi_simulator`，安装 requirements.txt，加载插件。
2. 在插件详情打开 dashboard 视图。所有访问通过 AstrBot View 桥接，后端要求 Dashboard 登录身份；没有独立公开入口。
3. 在“游戏与连接”选择行情源。新配置默认 biquote，免注册、免 Key；也可选择新浪，或保留 OANDA Practice 模拟账户。biquote 和新浪均预填可修改的默认链接，并提供恢复默认地址。
4. 点击“测试连通性”测试当前输入。测试返回服务器获取结果和耗时，不保存设置、不切换交易报价；点“保存行情设置”才生效。已有持仓／挂单时先结清再切换来源或地址。OANDA 令牌留空保留已存凭据。
5. 创建游戏，选择允许品种、资金、费用和可选挑战条件。
6. 为当前游戏选择平台已配置的模型和 AstrBot 人格，可手动看盘或开启定时看盘。
7. 如需聊天工具，在新建实例时绑定用户：会话 UMO 列表（推荐）、QQ 号或管理员生成的随机 ID 三选一。绑定让会话中的 AI 操作该用户的账户，不开放充值或改规则工具。同一用户可有多盘，聊天中需先选择实例；随机 ID 方式由每次工具调用的 user_id 携带。

OANDA 的模拟账户／API 可用性受所属实体和地区影响。项目不会代为注册，也没有内置凭据。OANDA 尚未使用真实凭据完成联调；biquote 和新浪已用插件实际适配器在开发电脑匿名连通，各返回六个货币对，不等同于用户服务器已验证。

## 当前明确的模拟规则

- 仅美元账户；六个主要货币对；数量为基础货币单位。
- 每品种可有多笔独立仓位，同向或反向均分别记录；按具体持仓ID平仓，不自动净额合并。每笔独立占用保证金、计费和设置止盈止损。
- 游戏杠杆上限 1～100，每笔订单可选择本次杠杆；强平阈值为交易资产（余额＋浮盈亏）/已用保证金低于 50%，优先平浮亏最大的仓位。
- 买入 ask、卖出 bid；止损跳空时按可得报价处理；普通报价超过 30 秒暂停成交。
- 行情每 10 秒批量读取一次快照，可能错过两次采样之间的瞬时触价，不冒充逐笔行情。
- 双边成交额比例手续费，无最低费。尚无固定费用和隔夜费用。
- 追加本金不计入净赚亏和时间加权收益。发生零或负净值时结束本局。
- 图表默认 K 线，可切换 OHLC、折线和面积图；打开载入历史，左拖到边界或点击按钮继续加载。后台每轮批量采集六个品种，独立保存各周期。资金净值历史曲线尚未实现。
- 游戏的暂停只暂停 AI 操作，系统止盈止损和强平继续生效。

## 数据

SQLite 数据库存于 AstrBot 插件数据目录的 `astrbot_plugin_kurumi_simulator/ledger.sqlite3`，包含真实行情配置凭据，请勿公开上传数据库。

账户、持仓、费用、统一日志、记忆和已获取的历史 K 线持久保存；旧报价不会跨重启假装有效。历史按报价源/配置隔离，切换来源不拼接不同市场价格。日志有成功和拒绝状态，账本修改使用事务，带请求 ID 的重复成功请求不会重复入账。

## AI 工具

在新建实例时绑定用户，确保当前人格允许工具调用。QQ/UMO 绑定按可信消息身份解析；随机 ID 方式由每次工具调用的 user_id 携带。工具只能访问当前用户选中的实例，不能操作他人的盘。

| 工具 | 用途 |
| --- | --- |
| kurumi_my_instances | 列出当前用户可操作的交易实例 |
| kurumi_select_instance | 在当前私聊选择要操作的实例 |
| kurumi_watch_market | 看实时报价、账户、持仓、规则、计划与近期交易日志 |
| kurumi_read_journal | 按货币对和日志ID分页查记录，包括人类追加资金 |
| kurumi_open_position | 开仓，可同时设置止损止盈，必须写理由 |
| kurumi_close_position | 平仓并结算费用、盈亏 |
| kurumi_set_protection | 修改已有持仓止损止盈；-1保留、0取消、正数设置 |
| kurumi_write_plan | 保存当前实例的完整交易计划，记录修改理由 |
| kurumi_write_memory | 兼容入口，仅保存交易计划；笔记暂不扩展 |
| kurumi_price_history | 读取真实历史K线辅助判断，不会下单 |
| kurumi_virtual_loan | 在人类允许的额度内借还虚拟资金，必须写理由 |
| kurumi_forex | 通用控制台兼容入口，供状态查询和其他受限操作使用 |

保护线由程序触发执行。价格关注线唤醒 LLM 尚未实现，二者不同。工具不允许 AI 自行充值、重置或改游戏规则。

安装包为 0.1.0 开发测试包；免密来源已本机匿名联调，OANDA 尚无真实凭据联调；没有配置有效行情时不会产生交易。开发测试包不是正式发布。

## 历史图表与交易工作台

- 左侧六品种观察列表，中间图表与持仓价格位置卡，右侧保证金下单、杠杆滑块与虚拟借还款。未被本局授权的品种可观察但不能交易。
- 图表类型：K 线、OHLC、折线、面积。周期：1/5/15分钟、1/4小时、日、周、月；周线按周一，月线按自然月聚合。OANDA使用原生周期。
- 首次最多加载200根，向左拖到边界继续取更早记录。分钟历史范围由上游决定，不能无限回溯；获取失败保留本地数据并显示提示。周/月线可能因历史长度不足少于200根。
- X轴时间和Y轴价格有标签，可拖动、缩放、双击复位；展开坐标轴设置可填写起止时间、价格范围，以及切换价格刻度、北京/UTC显示时区。
- 中间价 K 线只用于展示；成交使用所选来源的实时bid/ask。后台十秒采样并非完整逐笔行情，不伪造开盘前遗漏的价格路径。
- 默认新浪请求加Referer及浏览器请求头，失败时尝试同站参数式地址；仍失败会显示原因。不会自动切换到另一来源成交。自定义新浪地址不会偷偷替换为默认地址。
- 使用本地打包的 Lightweight Charts 5.0.9，保留许可证与 TradingView 标识；页面不需要从CDN载入图表库。

## 虚拟贷款规则

在创建游戏时选择本局是否可借款，并设置最大未偿本金；小金库只显示规则和提供借还操作。本金上限默认初始资金的2倍，日单利0.01%，按真实经过时间计息，结束时冻结未偿债务。贷款和偿还都写入统一日志。

借款增加余额和可用交易保证金，同时增加负债；账户净值、盈利和游戏胜负会扣除负债，因此不会凭借借钱获胜。偿还先付利息再还本金，不能动用已占保证金。人类追加本金是另外一项资金流，二者分开记录。关闭借款开关不会取消既有债务。界面金额为显示舍入，账本仍以十进制保存。

本地 Git 仓库已初始化，没有发布远端。本轮仍属0.1.0预览修订，不另外登记正式版本。


## 当前预览修订：默认历史来源和操作改进

- 历史默认 Frankfurter，每日参考汇率折线。周/月为该周期最后发布的参考价，没有日内开高低收，不能伪造分钟 K 线。要看真实分钟 K 线，可在连接设置将历史来源切为“所选实时行情源”。实时成交仍为biquote/新浪/OANDA三选一，历史选择不影响成交来源。

## 当前修正：多笔持仓与默认K线（preview5）

取消同品种单仓限制，支持多笔独立持仓。当前持仓数量统计账户尚未平仓的原始记录；即使报价失效无法估值，也显示真实笔数和持仓明细。日志显式区分“开仓·已成交”和“开仓·未执行”，拒绝记录直接展示原因。历史上已拒绝的订单不会凭空补成交，已平仓的订单也不计为当前持仓。

图表默认K线、5分钟，所有图形和周期都可选择。K线/OHLC及分钟周期自动请求所选实时行情源的真实历史数据，即使历史参考配置仍为Frankfurter也不会锁住控件。日/周/月折线或面积图才使用配置的参考来源。历史请求显式指定来源，仅作用于展示，不修改实时成交设置；两个来源各自缓存，不拼接、不拿每日参考价伪造蜡烛图。

81项单元测试通过，浏览器验证3笔持仓、拒绝状态、过期估值保留笔数、默认K线和来源切换，真实AstrBot验证展示来源覆盖不修改已保存设置。本轮仍为0.1.0开发预览修订。

## 用户与交易实例界面框架（preview7，仍为0.1.0）

顶部设置/交易实例两段切换；设置接收原游戏与连接内容，并预留用户/权限/实例上限入口。实例按用户分组，提供用户选择、实例选择与桌面分组目录；每个实例保留工作台/日志/计划与经验三个子页。总经验仅保留未启用入口。

现有无owner字段的数据列为“未分配用户”，没有自动迁移归属。此轮仅UI框架，不增加真实用户管理或访问隔离；当前仍受AstrBot Dashboard登录保护。后端按实例ID保存的数据独立不等于权限隔离完成。后续边界及鉴权顺序见docs/WORKSPACES.md。

本地浏览器用明确测试夹具验证2位用户/3个实例的分组、切换后的日志/经验呈现、顶部工作区与手机布局；不代表多用户安全测试或真实鉴权已完成。

## preview10：必填用户绑定、管理员随机ID和删除

顶部导航改为跟随屏幕滚动。新建必填用户绑定：UMO列表（推荐）、QQ号或管理员随机ID；支持可选昵称，空值使用持久递增用户名称，相同绑定复用用户。随机ID以 krm_ 开头，由管理员在设置页生成或刷新；刷新后旧ID立即失效，实例与交易数据不变，用户把ID交给LLM后由工具调用的 user_id 参数携带。身份绑定最初按本地账号密码设计，后改为随机ID，旧方案未保留。此轮没有独立用户登录或完整访问授权。

实例卡片与实例设置可删除，确认后删除该盘余额/持仓/日志/计划/经验和操作请求记录，保留用户账号、其他盘和行情缓存。删除墓碑与异步绑定复查防止旧请求写回。旧未归属实例保留为未分配用户。

106项单元测试通过：新增默认递增昵称、QQ/UMO/随机ID绑定复用与冲突、随机ID轮换失效、管理员生成用户、跨重启序号、删除隔离和防写回。真实AstrBot验证必填绑定、匿名删除拒绝、随机ID创建与绑定，以及删除期间的异步AI绑定不复活实例。浏览器验证三种绑定控件及提交、原样UMO提示、顶部滚动跟随、删除取消和确认。详细边界见docs/WORKSPACES.md。

行情接口默认值与显示名称集中在 `config/market.json`，包括实时、备用和历史接口；修改后重启插件生效。面板中已保存的自定义实时地址优先于文件默认值；可在面板恢复默认后保存。打包时需包含整个 `config` 目录。该文件不存放 API Key。

## 每日经验日记

在全局设置的「她的每日小记」配置每日写作。默认北京时间00:10写前一天，操作日志数严格大于2才生成；可开启「无交易但有聊天时也写日记」。全插件串行排队，失败和漏写会补写。正文在实例的「计划与经验」查看，聊天可通过 `kurumi_read_diary` 查询。使用实例已选模型/人格；聊天归档从启用后开始，旧聊天不补造。详见 [日记说明](docs/DIARY.md)。

## 用户权限与主动汇报

设置已按用户权限、API连接、日记分页。支持重命名、查看QQ/UMO绑定、实例数量上限和看盘间隔授权（默认1小时且禁止实例自行改）。新增自定义OpenAI兼容LLM与完整提示词调试开关。主动汇报及风险提醒默认开启，限定汇报时段默认关闭；所有主动消息均遵守默认00:00～07:00免打扰，包括爆仓。详见 [设置说明](docs/SETTINGS.md)。版本号保持0.1.0。

## 看盘队列与共享缓存

暂停按钮已移除；手动、定时和风险看盘统一排队限频，默认每实例最短10分钟、每小时最多6次。止损/止盈/强平/保证金/结束事件可触发LLM复盘，结束账户只读。K线先查共享缓存，不按实例重复下载。详见 [看盘与缓存说明](docs/DECISIONS.md)。
