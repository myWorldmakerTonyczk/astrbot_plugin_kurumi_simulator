# 每日经验日记

每个实例独立保存一篇日期日记，正文使用实例的决策模型和人格。全插件只有一条日记队列，日记之间不会并发请求；日记不会阻塞普通聊天或后台看盘，也不会发消息、下单或修改平台会话历史。

## 设置与条件

在全局设置的「她的每日小记」设置开关、时间（默认00:10）、时区（默认Asia/Shanghai）、交易操作日志阈值（默认2）和近期聊天条数（默认40，0～100）。

前一天的操作日志数必须**严格大于**阈值；默认2表示至少3条才写。包括成功/失败的交易、观望、计划、资金追加和借还款等操作，不将创建实例、模型看盘摘要、AI绑定设置或行情连接变更计入。

「无交易但有聊天时也写日记」默认关闭，开启后只对操作日志为0且有当日聊天的日期生效，不会绕过1～阈值条操作的限制。关闭日记也停止新的聊天归档；已有记录保留。

## 资料、权限与时间边界

对话归档从本功能安装启用后开始，通过框架聊天请求与发送完成事件收集文本。仅收集当前实例已授权的主参考私聊；模型请求、重试和发送完成重复触发不会重复归档同一消息角色。用户随机凭据从归档和模型输入中隐藏。

没有时间戳的现存 conversation.history 无法可靠划分日期，不会被冒充为某天的新聊天。旧实例可以补写既有交易日志，但旧聊天不完整时不能编造。语音或其他插件直接发送且未提供文本的消息不会凭空转录。

日记模型初次获得当日近期操作（最多50条）、配置数量的近期聊天、最近3篇旧日记与固定写作提示词。模型可通过专属只读工具继续分页查询本实例更早的操作、已归档对话和旧日记。查询截止时间始终为目标日结束，不提供当前账户/行情，避免补写读取未来信息。记录数量超出工具步数可覆盖的范围时，应坦诚资料不完整。

主参考会话的人格优先，未关联时使用实例设置的人格。日记不会将聊天或旧日记当作系统指令，不把偶然盈亏总结成已验证的盈利规律。

## 队列与补写

队列存储在原SQLite数据库的diaries表，以实例ID+日期唯一。每日到点以及插件重启后检查从实例创建日至应写日期的遗漏，不只检查昨天；原条件满足但没有成功日记的日期会入队。未达门槛的日期不排队。

失败后从5分钟起退避重试，最多间隔6小时；重启时将未完成running任务恢复pending。成功正文持久保存后不重复生成；网络中断发生在供应商已完成但本地尚未保存时，重试可能再次产生模型调用费用。取消任务也恢复排队。删除实例会级联清理其日记任务与对话归档。

面板「计划与经验」显示日记、排队与失败状态，可刷新或加载更早记录。旧notes保留在折叠区域。聊天和定时看盘均可通过kurumi_read_diary读取当前实例日记，用于后续复盘。

## 验证范围

离线测试覆盖严格阈值、纯聊天例外、过期任务补写、持久队列、串行生成、失败退避、取消与重启恢复、实例删除清理、权限和日期边界。真实AstrBot离线工具循环验证只读检索、人格引用、无未来聊天与正文保存。不代表已在用户云端或真实模型服务上验证写作效果。
