# 久留美模拟器：第一版计划

状态：待评审，尚未开始实现。日期：2026-11-04。

## 1. 产品目标

为 AstrBot 增加基于真实外汇行情的虚拟交易游戏。给 AI 一笔初始资金，让她自己观察、交易、犯错、积累经验，人类可以随时与她聊天、干预和复盘，也可以用独立账户参与。

目标是陪伴和探索，不预设盈利策略，不以盈利能力作为产品承诺。只告诉 AI 基本外汇规则和工具用法，具体交易风格由她自己摸索。

第一版完整面板集成在插件的 AstrBot View 中，不另行部署前端服务。本轮先完成计划，不编写插件代码。

## 2. 范围与阶段边界

第一版包含：真实行情、内部模拟账户、交易与费用、可组合游戏规则、AI 工具、定时和事件决策、交易日志、持仓计划、经验笔记、复盘，以及 View 面板。

QQ 中正常聊天调用交易工具、接收通知属于机器人能力；QQ 发送网页链接、独立网页入口、配对码登录和公开分享暂缓，不作为第一版依赖。第一版不提供未经鉴权的外部面板入口。

不接实盘，不要求券商交易账户，不连接真人资金；不做高频交易、完整订单簿撮合和复杂衍生品。

## 3. 行情来源与品种

- 采用“外部真实行情＋插件内部模拟记账”，不是把订单发送给券商。
- 候选主要货币对：EUR/USD、USD/JPY、GBP/USD、AUD/USD、USD/CHF、USD/CAD；最终以验证通过的数据源为准。
- 每局支持单一货币对或多个货币对；行情展示和交易权限分开，程序强制检查允许交易列表。
- 数据源采用适配器结构，初版先完成一个来源。优先验证带时间戳、买卖价、历史 K 线的接口；Twelve Data、OANDA Practice 作为调研候选，不预先承诺可用、免费或免注册。
- 开发前验证：云服务器可达性、账号及地域条件、价格字段、历史数据、持续额度、使用授权、休市状态。若未验证出满足条件的数据源，不能以随机价格冒充实时行情。
- 多账户共享行情连接和缓存。行情显示来源、市场时间、接收时间和是否过期。
- 行情断线或过期时暂停新成交及依赖报价的撮合，保留订单并展示异常；恢复后重新校验。
- 有真实 bid/ask 时直接使用；只有参考价时，明确显示为模拟点差。实时行情不意味着每一笔价格都能收到。

## 4. 游戏与账户

游戏保存：名称、绑定 AI、人设来源、决策模型、开始时间、初始资金、账户币种、交易品种、费用、杠杆与强平规则、胜负条件、运行状态。

初版账户币种以美元为主。一个游戏包含一个 AI 账户，可关联独立的人类账户进行比较；账户账本、持仓和资金相互隔离。

账户面板展示：

- 初始资金、累计追加、累计取出、累计净投入。
- 余额、浮动盈亏、净值、已用保证金、可用保证金、保证金水平。
- 扣费后净收益、排除资金流入流出影响的收益率、最大回撤、运行天数。
- 当前持仓、挂单、费用明细、强平次数、救场追加次数。

余额是已结算资金；净值包含未平仓盈亏。保证金是占用，不重复计作成本。无持仓时保证金水平展示为“不适用”。

追加本金不会当作盈利。采用资金流发生前后分段链接的收益率，金额净收益按净值减累计净投入计算；最大回撤基于排除外部资金流影响的净值指数。账户净值归零或为负时明确处理收益率不可继续链接的情况，不能静默产生错误比例。

## 5. 玩法预设与并行规则

预设只是规则模板，底层允许组合：

| 预设 | 内容 |
| --- | --- |
| 自由模式 | 只需设置初始金额；无游戏期限、胜负目标或额外策略限制，可随时追加资金 |
| 生存挑战 | 累计净亏金额或收益率触及阈值则失败 |
| 收益挑战 | 扣费后收益金额或收益率达到目标则获胜 |
| 限时挑战 | 到期结算；没有胜负条件时标记为到期结束 |
| 自定义 | 并行组合胜利、失败、时间、货币对及追加资金规则 |

自由模式仍受休市、资金、保证金、费用和强平等基本交易规则约束。

失败条件区分：累计净亏上限、净值绝对底线、收益率亏损阈值、最大回撤上限。追加资金不抹掉历史净亏，但可以抬高绝对净值，形成允许救场的玩法。

每次账户变化和定时检查均评估规则。任意结束条件触发就锁定结束流程；同一检查周期冲突时，失败优先于胜利，胜负优先于单纯到期。

结束流程：禁止新交易、撤销挂单、以可用行情结算持仓、记录最终成绩、停止自主决策、允许继续聊天复盘。休市或行情失效时进入“等待结算”，记录触发时成绩和实际结算成绩，不虚构成交价。

开局保存规则快照；中途可修改的规则由人类明确操作并记日志。比较成绩时展示追加资金及规则变更情况。

## 6. 模拟交易与费用

- 支持做多、做空、市价单、限价单、撤单、部分及全部平仓、止盈止损、修改止盈止损。
- 界面允许用交易单位输入，并辅助显示仓位名义价值；避免把“手数”与“货币单位”混淆。
- 初版同一账户同一品种采用净持仓模式；反向交易先减少或平掉原仓，超出部分再反向开仓，不实现双向锁仓。
- 市价买入使用 ask，卖出使用 bid；限价、止盈止损根据对应可成交方向报价触发。跳空时按定义的可得价格成交，不保证止损价。
- 杠杆是保证金规则上限，实际风险取决于仓位。使用统一美元换算计算名义敞口、保证金和跨币种盈亏。
- 强平阈值可配置；初版采用确定的逐仓平仓顺序，例如优先平亏损最大的仓位，直到满足恢复条件或无仓可平，并记录全过程。
- 不模拟真实市场排队、深度和部分流动性成交，面板说明这是简化模拟撮合。

费用包含：成交手续费、点差成本、可选隔夜费用。手续费支持固定金额或成交额比例及最低费用，明确是否双边收取；真实买卖价已有点差时不再额外扣一遍。

隔夜费用若没有可靠数据，使用明确标注的模拟费率，按指定时区和结算时间计算；重启后补算且不重复扣费。盈亏和费用都使用十进制定点计算及明确舍入规则。

## 7. AI 的三种操作时机

### 定时看盘

用户开启后，按设定间隔请求所选 LLM。提供最新状态和相关记忆，允许观望，不要求每次下单。行情更新频率与 LLM 决策频率分离。

### 事件唤醒

可选事件：价格穿越关注线、成交、止盈止损、保证金预警、异常恢复、追加本金等。AI 可通过工具自行创建、取消价格关注线。

事件去重、合并和冷却；价格线采用穿越触发及重新布防规则，避免价格在附近反复震荡刷请求。限制每轮工具次数、模型调用时长和事件调用预算。

止盈止损、强平和游戏结束由程序立即执行，再通知 AI；不等待 LLM 才执行基本规则。

### 人类聊天

沿用 AstrBot 当前聊天和人格，通过工具查询和操作绑定账户。用户可以质疑、建议、要求复盘，AI 自行判断是否采纳建议。明确的人类手动交易和资金操作记录为人类干预。

三类入口共用账户交易协调器；每账户操作串行化，执行前重取行情和账户状态。旧决策若状态已变化则重新校验或拒绝，防止重复下单。

## 8. 人设、上下文与长期记忆

采用 AstrBot 人设和模型能力，交易事实与经验独立持久化，不把整个长期交易过程依赖于普通聊天历史。

聊天决策沿用当前会话人格；后台决策明确绑定会话／人格来源及模型，复用框架可用的人格装配方式，避免仅凭机器人名称猜测人格。绑定失效时暂停并提示。

每次默认提供：基本交易规则、当前游戏规则、账户状态、持仓计划、近期重要日志、经验摘要、本次触发原因及所需行情。

持仓最初的开仓理由随持仓保留，不被“最近 N 条”截掉。日志、工具返回和历史文本都是分析资料，不作为更高优先级指令执行。

更久或更详细的日志由查询工具按时间、品种、操作类型检索。上下文有长度预算，优先保留当前事实与持仓计划，再选择相关历史；不把每次后台观望写入日常聊天历史。

额外保留：

- 持仓计划：开仓意图、退出条件、关注事项，变更时记日志。
- 经验笔记：由 AI 复盘后更新，区分假设与观察结果，引用日志编号，保留修订记录。
- 事实账本：由程序维护，不允许 AI 改写成交、余额或历史结果。

## 9. 统一交易日志

所有 AI、人类、系统操作写入同一时间线，每个操作对应一条日志。重要观望决定也记录；界面折叠重复观望，原始记录可查。

日志字段：唯一编号、游戏和账户、时间、来源及操作者、触发方式、操作类型、品种、数量、订单参数、理由概要、决策时行情快照、执行状态、成交详情、费用、操作后账户快照、关联日志和订单编号。

AI 在提交操作时填写简短理由，不要求输出隐藏推理过程。程序填写实际执行结果。人类可选填备注，未填显示“未填写理由”；系统事件自动写明触发原因。

一条操作日志先建立“待执行”记录，再补全最终结果；超时等不确定状态单独标记，重启后恢复核对，不直接当成失败重试。失败、拒绝、撤销均保留。

账本不可通过复盘覆盖。更正通过新增关联记录完成。可按账户、来源、品种、操作、时间筛选与分页。

## 10. LLM 工具与权限

初版工具能力组：

- 查询：品种、最新报价、K 线、账户、持仓、挂单、游戏规则。
- 操作：开仓、平仓、挂单、撤单、修改止盈止损。
- 记忆：检索日志、读取与更新持仓计划、读取与更新经验笔记。
- 唤醒：设置／删除价格关注线。
- 复盘：读取时期统计及交易结果，生成可保存的复盘报告。

工具绑定明确的授权账户，不能仅按模型传入的账户 ID 操作任意账户。人类身份依据平台可靠标识；创建、重置、追加本金、修改玩法等管理操作不向 AI 提供无条件执行能力。

所有交易都由程序验证品种、数量、市场状态、行情有效期、资金和规则。工具返回结构化执行结果和日志编号，AI 不得只凭自然语言宣称成交。

## 11. AstrBot View 面板

面板完全随插件安装，复用插件服务和数据，不另建一套账本。不要求安装独立前端服务。开发前核对当前 AstrBot View 路由、鉴权、接口和资源加载规范。

### 总览与交易

- 顶部：游戏／账户切换、玩法、行情状态、自主交易状态、暂停／继续。
- 指标卡：净值、扣费后净收益、收益率、最大回撤、运行天数、累计投入。
- 主区域：货币对选择、K 线与交易标记；资金曲线可切换金额与资金流调整后的表现。
- 侧栏：持仓、挂单、保证金、风险提示、人类交易表单。
- 底部：统一日志、AI 当前计划、最近复盘。
- AI 账户的人类交易明确标记为干预；自己的账户交易独立展示。

### 日志与复盘

时间线和表格切换；默认显示“操作、理由、结果”，展开查看行情快照和费用。支持指定交易、日／周／整局复盘，以及导出日志和结果。

### 游戏与配置

创建向导：初始金额 → 玩法预设 → 人格与模型 → 单一／多品种 → 开始。自由模式提供合理默认规则和费用说明，其他参数放在高级设置。

设置包含：行情源与连接测试、AI 决策模型下拉选择、人格／会话绑定、周期和事件、费用和杠杆、胜负规则、追加资金策略、通知频率、调试和数据管理。

手机纵向卡片布局；加载、断线、休市、模型忙碌、执行失败和等待结算有明确状态。避免默认堆砌专业术语，指标提供简短解释。

### 安全与访问

第一版仅从已授权的 AstrBot View 访问，后端每个读写接口都检查身份与权限，不只隐藏按钮。核实框架鉴权机制后复用；无法安全复用时先解决认证，不开放无鉴权接口。

密钥仅保存在服务端，前端脱敏，日志不输出密钥。管理操作校验权限、参数和请求来源，并提供适合框架的请求伪造防护。重置和删除数据需明确确认。

QQ 面板跳转及配对登录保留为后续扩展，第一版不实现。

## 12. 存储与运行可靠性

- SQLite 事务保存游戏、账户、资金流水、订单、成交、日志、持仓计划、经验笔记、复盘、事件订阅及规则版本。
- 所有入口共用领域服务，LLM、View、后台不能各自计算一套余额。
- 幂等键防重复操作，账户锁与数据库事务保证并发一致性。
- 数据目录遵循 AstrBot 插件数据规范，不放在会被插件更新覆盖的源码目录。
- 重启恢复订单、持仓、费用结算、游戏状态及调度；行情中断期间不声称捕捉到了全部触价事件。
- 卸载／重载时停止后台任务和连接；模型失败保留原状态，有限重试并展示原因。
- 只对重要事件通知聊天，设频率限制；失败不输出伪造的工具调用文本。

## 13. 建议代码结构

使用独立新项目，不混入现有语音插件。

```text
astrbot_plugin_kurumi_simulator/
  main.py                  # AstrBot 薄入口
  metadata.yaml
  _conf_schema.json
  requirements.txt
  src/
    plugin.py              # 生命周期与集成
    domain/                # 账户、规则、费用、盈亏、撮合
    market/                # 行情适配与缓存
    storage/               # SQLite 与迁移
    ai/                    # 请求装配、决策、记忆、复盘
    tools.py               # LLM 工具
    scheduler.py           # 周期和事件调度
    web/                   # View 后端接口
  views/                   # 按实际框架规范组织
  tests/
  docs/
```

具体注册方式和 View 文件命名以届时核对的 AstrBot 开发规范为准。

## 14. 实施顺序

1. 验证行情源和 AstrBot View／模型／人格接口，记录确定方案与额度。
2. 实现账户账本、费用、模拟成交和组合游戏规则。
3. 实现 View 的创建游戏、行情、账户、手动交易和日志闭环。
4. 注册 AI 工具，跑通聊天查盘及交易，接入统一交易记忆。
5. 加入定时看盘、事件唤醒、持仓计划和经验复盘。
6. 完成图表、统计、权限、重启恢复及异常处理。
7. 在测试账户验证，再打包供实际 AstrBot 安装体验；发布与版本号单独决定。

## 15. 第一版验收

- 用户在 View 创建自由模式，设置初始金额与 AI 后即可开始；无需单独安装网页服务。
- 行情确实来自已验证接口，展示来源和时间；断线不使用过期报价继续成交。
- AI、人类、系统操作均可追溯到统一日志，金额与理由来源清楚。
- 定时、事件、聊天三入口都能操作，重复触发和并发不会重复下单。
- 做多做空、平仓、挂单、止盈止损、费用、保证金和强平计算有有意义的测试覆盖。
- 追加资金不会冒充收益，胜负和回撤规则可验证，结束状态不能继续自主交易。
- 模型能读取跨聊天历史截断的持仓理由和相关旧记录，同时保持所绑定人格。
- 重启后账本、挂单、计划和经验仍在；费用不重复扣除。
- 未授权访问无法查询或操作账户；密钥不进入页面响应或普通日志。
- 实际行情、模型和服务器的联调结果与尚未验证的部分分别说明，不把源码检查当作运行验证。

## 16. 已达成的产品约定

名称“久留美模拟器”；重在与 AI 一起玩而非追求盈利；真实行情、纯虚拟资金；统一交易日志；采用框架人设＋独立交易记忆；三类决策入口；多玩法和并行胜负规则；允许受规则控制的人类追加资金；面板集成 AstrBot View；QQ 网页入口暂缓。
