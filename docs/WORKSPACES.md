# 用户与交易实例：界面框架

当前已实现新实例的用户绑定元信息、管理员随机ID发放与核验和实例删除。仍通过现有AstrBot Dashboard登录门禁访问，没有独立登录页、访问授权隔离、配额或开放QQ链接。目录分组不等于权限隔离。

## 信息结构

顶部“设置 / 交易实例”，默认进入交易实例。

设置：用户与权限（占位）、新建实例及开局规则、全局行情连接、当前实例的AI/人格/UMO绑定。

交易实例首页：中央按用户展开卡片目录；未选择实例时侧栏整体隐藏，不自动进入第一盘。点击具体实例后进入工作台，才出现左侧工作台/日志/计划与经验导航。通过“所有交易实例”返回目录；顶部“交易实例”也返回目录。手机使用同一目录布局。没有任何实例时保留原欢迎页和“创建第一局”入口。设置仍独立；未选择实例时隐藏AI绑定表单。

智能体总经验放置未启用入口，不创建共享存储，不把任意实例私有日志自动汇总。

## 领域边界（后续实现）

- User：稳定user_id，来自可信身份映射，不能信任QQ昵称或浏览器传入的owner_id。
- TradingInstance：现有games.id可沿用作为instance_id；以后增加owner_id、成员权限、quota等元信息。实例不等同于聊天会话，一项UMO是调用入口绑定，不是数据归属证明。
- 实例数据：账户余额/持仓/规则/日志/计划/实例经验按instance_id隔离。目前账本已按游戏ID存储这些内容，但没有校验请求人是否拥有该实例，不能因此声称多用户隔离完成。
- 人格和智能体：与实例分开。智能体总经验后续可以按agent_id独立保存；只有明确的通用经验提炼过程才可写入，不默认共享聊天或交易原文。
- 行情：公共历史可以共享缓存。用户的密钥、会话内容与资金日志不作为公共缓存；将来用户自配密钥要单独定义归属与管理权限。

## 当前呈现模型

instance-catalog.js接受games列表和可选users目录。游戏存在owner_id时按其分组，缺少归属的现有数据归入“未分配用户”。新实例由创建表单填写QQ/UMO列表/管理员随机ID，真实后端生成owner_id和users目录；遗留无归属实例仍为未分配用户。录入绑定不等于验证访问者本人身份，前端展示字段不作为授权依据。

未来可由state.workspace.users提供{id,name}列表、games提供owner_id/owner_name；其他底层接口继续接受实例ID。该字段是预留呈现约定，尚非用户管理API。

## 后续鉴权接入顺序

1. 确认身份来源和管理员定义，再实现User/Instance/Member映射与遗留数据归属迁移。遗留未归属数据先限管理员可见，不默认归入第一个访问者。
2. 后端统一resolve_instance(principal, instance_id, permission)，覆盖state/command/alerts/decision/日志/配置读写。先过滤列表，再核验单实例；隐藏按钮不能替代校验。
3. QQ/聊天工具使用可信平台ID解析principal，并绑定instance_id；禁止工具通过自填owner_id或UMO取得其他人的盘。
4. 定时AI任务按实例保存的归属执行，不能借用Dashboard管理员身份。校验实例是否仍启用、额度、并发与成员权限。
5. 加入用户实例数量限制、创建权限、删除和导出规则；最后再考虑分享链接与独立面板鉴权。
6. 做越权与隔离测试：跨用户猜ID、请求体换ID、历史提醒游标、后台任务及用户密钥。

本轮不实现以上授权流程，也不引入默认共享的总经验。现有交易逻辑、数据格式和正式版本号保持。

## preview9：全局设置与实例弹窗

顶部同排放“设置 / 交易实例 / 所有交易实例”，没有吸顶定位。交易实例页签可以返回当前选中的实例，所有交易实例始终清除选择并返回中央目录。

全局设置只保留API/行情连接与用户权限占位。新建实例打开独立dialog，装载既有资金/杠杆/借款/品种/挑战表单；已有实例通过实例设置dialog修改既有AI/人格/UMO绑定。中途修改玩法等功能只留说明，没有新建后端规则修改接口。

提醒仅在对应实例视图活跃期间读取和弹出；进入目录、全局设置或配置弹窗会离开提醒范围，清理该实例待显示的提醒。异步响应带范围版本检查，退出后返回的旧请求不会弹窗。重新进入时建立新基线，不追弹离开期间的旧记录。前台全局配置错误仍可在对应操作处提示。

仍然只是UI/交互框架，用户归属和真实多用户授权尚未实现。


## preview10：用户绑定、随机ID核验与删除

- 创建API要求user_binding；QQ号、私聊UMO列表、管理员随机ID三选一。UMO为默认推荐，提示按用户提供的/sid格式；列表每行一个，最多20条。多个UMO声明为同一用户，若已分别属于不同用户则拒绝自动合并。
- sim_users保存稳定ID、昵称与序号，sim_user_aliases保存绑定别名。同一绑定复用已有用户和昵称，空昵称以持久递增计数器生成“用户1、用户2…”。三种绑定类型不自动互相推断或合并；不同平台的数字session_id不冒充QQ号。
- 随机ID由管理员在设置页生成，格式为 krm_ + 20位十六进制，明文显示在用户列表，可随时刷新；刷新后旧ID立即失效，实例与交易数据不变。随机ID是bearer凭据，用户交给LLM后由每次工具调用的 user_id 参数携带；不会写入game对象、交易日志或工具理由，随机绑定的 user_binding.values 为空。尚未增加用户登录、重置密码及按账户限制访问的流程。
- QQ/UMO是管理员录入的归属元信息，未校验QQ在线身份。聊天工具入口UMO仍是独立选项，不因用户归属自动获得工具操作权限；同一工具入口多个实例时保持原有拒绝歧义行为。
- 删除只允许当前Dashboard管理请求，卡片和实例设置均提供二次确认。删除指定games记录及其logs/requests，保留用户与随机ID、公用行情及其他实例。建立删除墓碑拒绝旧对象写回，AI绑定在异步查人格后重新读取实例，避免删除时被旧请求复活。
- 旧数据不会自动迁移。实例删除后浏览器读取到missing_instance会返回目录。未来仍需为所有state/command/alerts/decision/工具接入统一的真实授权检查。
- 顶部导航现为sticky跟随视口；页面向下滚时仍可操作。移动端侧栏不再吸顶，避免与导航重叠。
