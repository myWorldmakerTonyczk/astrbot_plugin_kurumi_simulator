# 用户管理、模型接口和主动汇报

设置拆成「用户与权限」「API与行情连接」「每日日记」三个独立分页，保留现有久留美主题。

## 用户与权限

虚拟用户可重命名，随机ID刷新后立即使旧ID失效。用户卡片默认全部收起，点击展开后显示QQ / UMO绑定、所属实例及主参考会话；改名同步所有实例的显示名称，不更改内部身份、交易或日记数据。

每位用户可设置实例数量上限，0表示不限；降低上限不删除已有实例，只限制继续创建。默认看盘间隔1小时、最小10分钟，默认不允许在实例面板修改。后台按有效权限计算实际间隔，实例接口不能通过伪造字段绕过限制。管理员处与实例面板共用同一用户级间隔；获准后在任一处修改，都会同步该用户全部实例。旧配置小于10分钟时，实际生效值至少为10分钟。

主动通知的实例面板修改权限与AI工具修改权限分别控制，默认均允许。管理员在用户卡片修改通知默认值时同步全部实例；仅改昵称/权限保留实例原有通知偏好。新实例继承用户默认值。控制台仍由AstrBot管理员登录访问，这些用户ID不是新的网页登录账号。

## LLM连接与调试

默认使用平台模型，默认不代选，保存时须手动选择。已保存的选择会保留。另一方式为自定义OpenAI兼容Base URL、模型名、API Key、可选JSON请求头与超时，须支持Chat Completions和工具调用。

后台看盘与日记统一走此路由。自定义模式每次创建独立Provider并通过私有Context副本运行平台工具循环，结束后关闭连接，不修改AstrBot全局提供商或普通聊天模型。密钥和请求头保存在服务器设置中，不向页面回显；留空保留，输入{}清空已存请求头。

「在控制台输出完整LLM提示词」默认关闭。开启后打印每次看盘/日记任务送入工具循环的完整system_prompt、contexts和prompt，插件不截断；随机用户凭据作隐藏处理，不输出配置的API密钥/请求头。后续工具执行仍有框架自身的工具日志。这不是普通聊天全局调试开关。

## 主动汇报与免打扰

主动汇报总开关、爆仓/强平、保证金不足、追加资金和本局结束通知默认开启；「看盘完成后汇报」「限定汇报时段」「在时段内随机延迟发送」默认关闭。启用看盘汇报和限定时段后，若同时启用随机延迟，则每次看盘在允许范围内选择发送时间，并非每天只汇报一次；未启用随机时选最早可发时间。多次分析尚未发送时合并最新摘要，保留原待发时间以免不断推迟。

默认通知时区Asia/Shanghai，免打扰黑名单00:00～07:00。所有主动消息均受黑名单约束，爆仓和保证金事件也不能绕过；排队到禁发结束后再发。风险通知不受普通看盘的可选汇报时段限制，但始终遵守免打扰。支持跨午夜时段，完全被黑名单覆盖的汇报时段会拒绝保存。

发送前再次读取本实例当前开关、时段、黑名单及授权会话；长批次逐条读取实际时间，避免上一条发送期间跨入午夜而继续发送。通知只能去已授权的主参考私聊；尚未关联时保留失败状态并重试，不从QQ号猜测平台路由。普通用户聊天回复不经过此主动消息队列。

聊天和后台智能体可在管理员允许时调用kurumi_set_notifications调整当前实例，不能改别人的配置。日记不主动推送。

通知使用持久SQLite游标与outbox，升级首次不回放历史事件，重启保留待发记录。发送失败自动退避重试；平台接受消息后若确认丢失，重试仍可能重复，未宣称外部消息严格只送达一次。

实例保存改为SQLite原地UPSERT，避免替换父记录引发外键级联误删日记、聊天或待发通知；删除实例才级联清理对应记录。

## 已验证范围

离线规则测试、真实AstrBot工具/接口运行时验证与桌面/手机浏览器检查。自定义API采用本地HTTP模拟，验证真实工具循环、请求头/密钥/模型、连接关闭及平台状态不变；未向真实用户或实际云端模型发送测试请求。

## 折叠、必填与用户删除

用户卡片默认全部收起，展开后再显示内部绑定、权限和通知板块。设置中的必填控件为空时在标签旁显示红色「（必填）」，填入后消失；未启用/禁用字段不显示此提示。平台模型以「请选择」开始，不自动选首个模型；自定义模式的Base URL与模型名按模式动态必填。

用户删除使用独立确认框。确认后删除该用户全部实例、日志、计划、日记、通知队列及QQ/UMO绑定和随机ID；其他用户保留。实例墓碑防止进行中的后台任务把已删实例写回。该按钮位于展开后的用户卡片中。
